# 개발 워크플로우 규범

## 1. 프로젝트 초기화와 문서 체계

### 라이트 모드 (코드량 < 500줄)
`README.md`만 있으면 되며, 다음을 포함합니다: 프로젝트 소개, 기술 스택, 핵심 테이블 구조, API 목록, 배포 절차.

### 일반 모드 (코드량 ≥ 500줄)
프로젝트 시작 시 다음 문서 구조를 생성합니다:

```
📁 /docs/
├── architecture.md      # 기술 스택 선정 이유(생활 속 비유), 시스템 아키텍처 다이어그램(Mermaid), 디렉터리 구조
├── dev_log.md           # 개발 로그: 시간, 변경 사항, 테스트 결과, 알려진 문제 및 해결 방안
├── api_interface.md     # 프론트엔드-백엔드 API 계약 (URL, 파라미터, 반환값, 예외 시나리오)
└── SNAPSHOT.md          # 핵심 스냅샷 (≤200줄): 기술 스택 버전, 테이블명 목록, API 경로, 비즈니스 플로우 차트
```

Token 최적화: 매 대화 종료 시【컨텍스트 요약】(진행 상황, 변수명, 할 일, 재개 암호)을 생성합니다.

## 2. 프론트엔드 시각화 위치 결정 프로토콜

프론트엔드 코드를 작성하기 전에 먼저 다음 위치 정보를 출력합니다:

### 1. 페이지 레이아웃 다이어그램
ASCII 와이어프레임 또는 Mermaid 컴포넌트 트리로 페이지 구조를 명확히 합니다.

### 2. UI 요소 매핑 테이블

| 시각적 위치 | 컴포넌트 이름 | 해당 파일 경로 | CSS 클래스명/ID | 기능 설명 |
|---------|---------|------------|------------|---------|
| 상단 내비게이션 바 오른쪽 | UserAvatar | /src/components/Header.tsx | .user-avatar | 사용자 아바타 및 드롭다운 메뉴 |

### 3. 프론트엔드 이벤트 매핑 테이블

| 이름 | 동작 | 호출하는 백엔드 API | 기대 효과 |
|-------|------|------------|---------|
| 로그인 버튼 | 클릭 | POST /api/login | 홈페이지로 이동, Token 저장 |

## 3. 배포와 재해 복구 메커니즘

### 로컬 백업
- 원클릭 백업 스크립트 `backup.sh`를 제공하여 코드 + 설정 + 데이터베이스를 `./local_backup/`으로 내보냅니다
- 매 배포 전에 로컬 백업이 존재하는지 확인하고, 없으면 배포를 거부합니다

### 클라우드 서버 그레이스케일 롤백
- 새 코드 배포 전에 기존 버전을 `backup_타임스탬프.zip`으로 자동 압축합니다
- 긴급 롤백 3단계 절차:
  1. `./rollback.sh latest` — 최신 백업 압축 해제
  2. `docker-compose restart`(또는 `pm2 restart all`)
  3. `./health_check.sh` — 서비스 상태 출력
- `dev_log.md`에 백업 시간, 경로 및 롤백 기록을 남깁니다

### 환경 분리
- 개발/프로덕션 환경 설정을 구분합니다
- 프로덕션 환경에서 수정해야 할 보안 설정 항목을 미리 안내합니다

## 4. 요구사항 확장과 제안

사용자가 지정한 기능을 완성한 후,《기능 개선 제안 카드》를 출력합니다:

- ✅ **완료된 기능 요약** — 현재 사용 가능한 기능을 명확히 설명
- 🔮 **잠재 위험 경고** — 동시 접속, 데이터 일관성, 타사 의존성 등
- 🚀 **추천 확장 기능** — 우선순위 P0/P1/P2, 구현 난이도 ⭐, 기대 효과 표시
- ⚠️ **초보자 함정 회피 가이드** — 흔한 오해, 조작 시 주의사항

## 5. 테스트와 자가 점검 폐루프

### 최소 검증 가능 테스트 케이스
사용자가 직접 조작해 확인할 수 있는 검증 절차를 제공합니다. 예:
> "로그인 버튼을 클릭하고 올바른 계정/비밀번호를 입력한 후, 홈페이지로 성공적으로 이동하는지 확인하세요"

### 로직 정합성 선언
코드 출력 후 반드시 선언합니다:
> "자가 점검을 완료했습니다: ① 변수 스코프 올바름 ② 비동기 처리 완전함 ③ 예외 포착 범위 완전함 ④ 민감 정보 유출 없음 ⑤ 뚜렷한 성능 병목 없음"
