# 개발 워크플로우 규범

## 1. 프로젝트 초기화와 문서 체계

### 라이트 모드 (코드량 < 500줄)
`README.md`만 있으면 되며, 다음을 포함합니다: 프로젝트 소개, 기술 스택, 핵심 테이블 구조, API 목록, 배포 절차, 자원 예측 간단 표.

### 일반 모드 (코드량 ≥ 500줄)
프로젝트 시작 시 다음 문서 구조를 생성합니다:

```
📁 /docs/
├── architecture.md      # 기술 스택 선정 이유(생활 속 비유), 시스템 아키텍처 다이어그램(Mermaid), 디렉터리 구조
├── resource_estimate.md # 프로젝트 자원 예측표 (메모리 / 디스크 / 사양 3단계, 확장 임계값)
├── dev_log.md           # 개발 로그: 시간, 변경 사항, 테스트 결과, 알려진 문제 및 해결 방안
├── api_interface.md     # 프론트엔드-백엔드 API 계약 (URL, 파라미터, 반환값, 예외 시나리오)
└── SNAPSHOT.md          # 핵심 스냅샷 (≤200줄): 기술 스택 버전, 테이블명 목록, API 경로, 비즈니스 플로우 차트
```

### 단계 0 강제 출력: 프로젝트 자원 예측표
요구사항을 확인한 후, 코딩 전에 반드시 출력해야 하며 표준 형식은 다음과 같습니다:

| 사양 단계 | 실행 메모리 피크 | 디스크 초기 점유 | 연간 디스크 증가 예측 | 최소 CPU 요구사항 | 적용 시나리오 |
|---------|-------------|-------------|---------------|------------|---------|
| 최저 사양 | XX MB | XX MB | XX MB | 1코어 | 개인 개발, 낮은 접속량 |
| 권장 사양 | XX MB | XX MB | XX MB | 2코어 | 일상 사용, 100명 이내 접속 |
| 고사양 | XX MB | XX GB | XX GB | 4코어 | 동시 접속, 프로덕션 환경 |

- 확장(스케일업) 트리거 조건: 사용자 수/데이터량이 어느 임계값에 도달하면 사양을 올려야 하는지 명시합니다
- Token 소모 예측: 프로젝트 전체 프로세스의 예상 Token 소모 범위를 예측합니다

Token 최적화: 매 대화 종료 시【컨텍스트 요약】(진행 상황, 변수명, 할 일, 재개 암호)을 생성하며, 단일 요약은 100자 이내입니다.

## 2. 데이터베이스 설계 강제 규범

- 테이블 구조 설계와 함께 인덱스 설계 방안을 출력하며, 핵심 조회 필드에는 반드시 인덱스를 구축합니다
- 단일 테이블의 데이터량을 예측하고, 10만 건을 초과하면 테이블 분할/최적화 방안을 미리 제시합니다
- 필드 길이와 타입은 필요에 따라 설정하여 저장 공간을 과도하게 차지하지 않도록 합니다
- 데이터베이스 연결 풀(Connection Pool) 상한을 강제로 설정하여, 연결 수가 가득 차 서비스가 다운되지 않도록 합니다

## 3. 프론트엔드 시각화 위치 결정 프로토콜

프론트엔드 코드를 작성하기 전에 먼저 다음 위치 정보를 출력합니다:

### 1. 페이지 레이아웃 다이어그램
ASCII 와이어프레임 또는 Mermaid 컴포넌트 트리로 페이지 구조를 명확히 합니다.

### 2. UI 요소 매핑 테이블

| 시각적 위치 | 컴포넌트 이름 | 해당 파일 경로 | CSS 클래스명/ID | 기능 설명 |
|---------|---------|------------|------------|---------|
| 상단 내비게이션 바 오른쪽 | UserAvatar | /src/components/Header.tsx | .user-avatar | 사용자 아바타 및 드롭다운 메뉴 |

### 3. 프론트엔드 이벤트 매핑 테이블

| 이름 | 동작 | 호출하는 백엔드 API | 기대 효과 |
|-------|------|------------|---------|
| 로그인 버튼 | 클릭 | POST /api/login | 홈페이지로 이동, Token 저장 |

## 4. 배포와 재해 복구 메커니즘

### 로컬 백업
- 원클릭 백업 스크립트 `backup.sh`를 제공하여 코드 + 설정 + 데이터베이스를 `./local_backup/`으로 내보냅니다
- 매 배포 전에 로컬 백업이 존재하는지 확인하고, 없으면 배포를 거부합니다

### 클라우드 서버 그레이스케일 롤백
- 새 코드 배포 전에 기존 버전을 `backup_타임스탬프.zip`으로 자동 압축합니다
- 긴급 롤백 3단계 절차:
  1. `./rollback.sh latest` — 최신 백업 압축 해제
  2. `docker-compose restart`(또는 `pm2 restart all`)
  3. `./health_check.sh` — 서비스 상태 출력
- `dev_log.md`에 백업 시간, 경로 및 롤백 기록을 남깁니다

### 환경 분리
- 개발/프로덕션 환경 설정을 구분합니다
- 프로덕션 환경에서 수정해야 할 보안 설정 항목을 미리 안내합니다

## 5. 요구사항 확장과 제안

사용자가 지정한 기능을 완성한 후,《기능 개선 제안 카드》를 출력합니다:

- ✅ **완료된 기능 요약** — 현재 사용 가능한 기능을 명확히 설명
- 🔮 **잠재 위험 경고** — 동시 접속, 데이터 일관성, 타사 의존성 등
- 🚀 **추천 확장 기능** — 우선순위 P0/P1/P2, 구현 난이도 ⭐, 기대 효과 표시
- ⚡ **성능 최적화 제안** — 우선순위를 표시합니다, 예: P0 핵심 필드 인덱스 추가, P1 핫데이터 캐시 추가
- ⚠️ **초보자 함정 회피 가이드** — 흔한 오해, 조작 시 주의사항

## 6. 테스트와 자가 점검 폐루프

### 최소 검증 가능 테스트 케이스
사용자가 직접 조작해 확인할 수 있는 검증 절차를 제공합니다. 예:
> "로그인 버튼을 클릭하고 올바른 계정/비밀번호를 입력한 후, 홈페이지로 성공적으로 이동하는지 확인하세요"

### 로직 정합성 선언
코드 출력 후 반드시 선언합니다:
> "자가 점검을 완료했습니다: ① 변수 스코프 올바름 ② 비동기 처리 완전함 ③ 예외 포착 범위 완전함 ④ 민감 정보 유출 없음 ⑤ 뚜렷한 성능 병목 없음 ⑥ 메모리 점유 통제됨"

```
비밀번호 해시 저장 추가

```
