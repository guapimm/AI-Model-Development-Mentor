# 보안 규범 상세 매뉴얼

## 1. 키와 설정 관리

- 코드에 키, 비밀번호, API Token을 하드코딩하는 것을 금지합니다
- 환경 변수로 통일하고, 코드에서는 변수명만 참조합니다
- 모든 설정 항목을 `.env.example` 파일로 분리합니다 (실제 값 없이 변수명만 나열)
- 프로덕션 환경의 `.env` 파일은 `.gitignore`에 추가합니다

## 2. 사용자 입력 검증

- 모든 사용자 입력에 타입 검증을 수행해야 합니다 (예: 숫자 필드에 문자열 거부)
- 합리적인 길이 제한을 설정합니다 (예: 사용자 이름 2-50자)
- 특수 문자 주입을 거부합니다 (SQL 키워드, HTML 태그 등)
- 파일 업로드는 타입과 크기를 제한하고, MIME 타입을 검증합니다

## 3. 데이터베이스 보안

- 반드시 파라미터화 쿼리 또는 ORM 사전 컴파일 문을 사용합니다
- SQL 문자열 연결을 금지합니다
- 민감 필드(비밀번호)는 반드시 해시로 저장합니다 (bcrypt/argon2)
- 데이터베이스 연결 문자열의 비밀번호는 환경 변수를 사용합니다

## 4. 프론트엔드 XSS 방어

- 동적으로 렌더링되는 모든 콘텐츠는 반드시 HTML 이스케이프 처리합니다
- 프레임워크 내장 이스케이프 메커니즘을 사용합니다 (예: React의 `{}`, Vue의 `{{}}`)
- `innerHTML` 또는 `v-html`로 사용자 입력을 직접 렌더링하는 것을 금지합니다
- Cookie에 `HttpOnly`와 `Secure` 플래그를 설정합니다

## 5. 파일 시스템 보안

- 모든 파일 경로 작업을 검증하여 디렉터리 트래버설(`../`)을 방지합니다
- 화이트리스트를 사용해 접근 가능한 디렉터리 범위를 제한합니다
- 업로드 파일은 원본 파일명을 유지하지 않고 임의의 UUID로 이름을 바꿉니다

## 6. 외부 요청 보안

- 모든 HTTP 요청에 타임아웃을 설정합니다 (5-10초 권장)
- 재시도 정책을 구현합니다 (최대 3회, 지수 백오프)
- SSL 인증서를 검증하며, 인증서 검증 생략을 금지합니다

## 7. 예외 처리

- 모든 예외는 try-catch로 포착해야 합니다
- 프로덕션 환경에서 클라이언트에 원본 스택 정보를 반환하지 않습니다
- 오류 로그를 기록합니다 (시간, 요청 ID, 오류 유형 포함)
- 민감 작업(로그인 실패, 권한 부족)은 감사 로그를 기록합니다

## 8. 성능 보안

- API의 성능 병목을 고려하고, 필요 시 캐시(Redis)를 추가합니다
- 느린 쿼리를 최적화하고 데이터베이스 인덱스를 추가합니다
- 대용량 파일 업로드는 분할(청크) 또는 스트리밍 처리합니다
- 리소스 고갈 공격을 방지합니다 (요청 빈도 제한)
