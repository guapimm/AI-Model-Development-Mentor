# 安全规范详细手册
## 一、密钥与配置管理
- 禁止在代码中硬编码任何密钥、密码、API Token
- 统一使用环境变量，代码中仅引用变量名
- 所有配置项抽离到 `.env.example` 文件（不含真实值，仅列变量名）
- 生产环境 `.env` 文件加入 `.gitignore`

## 二、用户输入校验
- 所有用户输入必须做类型校验（如数字字段拒绝字符串）
- 设置合理的长度限制（如用户名 2-50 字符）
- 拒绝特殊字符注入（SQL 关键字、HTML 标签等）
- 文件上传限制类型和大小，校验 MIME 类型

## 三、数据库安全
- 必须使用参数化查询或 ORM 预编译语句
- 禁止字符串拼接 SQL
- 敏感字段（密码）必须哈希存储（bcrypt/argon2）
- 数据库连接字符串中的密码使用环境变量
- 强制配置数据库连接池上限，避免连接数打满服务崩溃

## 四、前端 XSS 防护
- 所有动态渲染的内容必须经过 HTML 转义
- 使用框架内置的转义机制（如 React 的 `{}`、Vue 的 `{{}}`）
- 禁止直接使用 `innerHTML` 或 `v-html` 渲染用户输入
- Cookie 设置 `HttpOnly` 和 `Secure` 标志

## 五、文件系统安全
- 所有文件路径操作必须校验，防止目录穿越（`../`）
- 使用白名单限制可访问的目录范围
- 上传文件重命名为随机 UUID，不保留原始文件名
- 单文件大小设置硬上限，超大文件强制分片上传

## 六、外部请求安全
- 所有 HTTP 请求必须设置超时（建议 5-10 秒）
- 实现重试策略（最多 3 次，指数退避）
- 验证 SSL 证书，禁止跳过证书校验

## 七、异常处理
- 所有异常必须有 try-catch 捕获
- 生产环境不返回原始堆栈信息给客户端
- 记录错误日志（含时间、请求ID、错误类型）
- 敏感操作（登录失败、权限不足）记录审计日志

## 八、性能与资源安全
- 所有列表接口默认开启分页，单页最大条数限制（默认100条），禁止全量查询
- 按预估并发量配置接口限流（IP级+用户级），防止资源耗尽攻击
- 大文件/大数据处理采用流式读写，避免一次性加载到内存导致溢出
- 核心查询字段必须建立索引，禁止无索引的全表扫描
- 定时清理过期日志与临时文件，控制磁盘占用无限制增长
