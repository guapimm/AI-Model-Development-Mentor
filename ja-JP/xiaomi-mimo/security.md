# セキュリティ仕様詳細マニュアル

## 一、秘密鍵と設定の管理

- コード内に秘密鍵、パスワード、API Token をハードコーディングすることを禁止する
- 一律で環境変数を使用し、コード内では変数名のみを参照する
- すべての設定項目は `.env.example` ファイルに分離する（実際の値は含めず、変数名のみを列挙する）
- 本番環境の `.env` ファイルは `.gitignore` に追加する

## 二、ユーザー入力の検証

- すべてのユーザー入力に型検証を行う（例：数値フィールドは文字列を拒否する）
- 妥当な長さ制限を設定する（例：ユーザー名は 2〜50 文字）
- 特殊文字の注入（SQL キーワード、HTML タグなど）を拒否する
- ファイルアップロードは種類とサイズを制限し、MIME タイプを検証する

## 三、データベースのセキュリティ

- 必ずパラメータ化クエリまたは ORM のプリコンパイル文を使用する
- SQL の文字列連結を禁止する
- 機密フィールド（パスワード）はハッシュ化して保存する（bcrypt/argon2）
- データベース接続文字列内のパスワードには環境変数を使用する
- データベース接続プールの上限を必ず設定し、接続数が上限に達してサービスがダウンするのを防ぐ

## 四、フロントエンドの XSS 対策

- 動的に描画するすべてのコンテンツは HTML エスケープする
- フレームワーク標準のエスケープ機構を使用する（例：React の `{}`、Vue の `{{}}`）
- `innerHTML` や `v-html` によるユーザー入力の直接描画を禁止する
- Cookie に `HttpOnly` と `Secure` フラグを設定する

## 五、ファイルシステムのセキュリティ

- すべてのファイルパス操作を検証し、ディレクトリトラバーサル（`../`）を防ぐ
- ホワイトリストを使用してアクセス可能なディレクトリ範囲を制限する
- アップロードファイルはランダムな UUID にリネームし、元のファイル名を保持しない
- 単一ファイルのサイズにハード上限を設定し、超大ファイルは強制的にチャンク分割アップロードを行う

## 六、外部リクエストのセキュリティ

- すべての HTTP リクエストにタイムアウトを設定する（推奨：5〜10 秒）
- リトライ戦略を実装する（最大 3 回、指数バックオフ）
- SSL 証明書を検証し、証明書チェックのスキップを禁止する

## 七、例外処理

- すべての例外は try-catch で捕捉する
- 本番環境ではクライアントに生のスタックトレースを返さない
- エラーログを記録する（日時、リクエスト ID、エラータイプを含む）
- 機密性の高い操作（ログイン失敗、権限不足）は監査ログを記録する

## 八、パフォーマンスとリソースのセキュリティ

- すべての一覧 API はデフォルトでページングを有効にし、1 ページあたりの最大件数を制限する（デフォルト 100 件）。全量クエリを禁止する
- 想定される同時アクセス数に応じて API のレート制限（IP レベル＋ユーザーレベル）を設定し、リソース枯渇攻撃を防ぐ
- 大ファイル/大量データの処理にはストリーミング読み書きを採用し、一度にメモリへ読み込んでオーバーフローを引き起こさないようにする
- 中核の検索フィールドには必ずインデックスを設定し、インデックスなしの全テーブルスキャンを禁止する
- 期限切れのログと一時ファイルを定期的にクリーンアップし、ディスク使用量が無制限に増加しないよう管理する
