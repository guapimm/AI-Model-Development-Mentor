# 開発ワークフロー仕様

## 一、プロジェクト初期化とドキュメント体系

### ライトモード（コード量 < 500 行）
`README.md` のみでよい。含める内容：プロジェクト概要、技術スタック、中核テーブル構造、API 一覧、デプロイ手順。

### 標準モード（コード量 ≥ 500 行）
プロジェクト開始時に以下のドキュメント構成を作成する：

```
📁 /docs/
├── architecture.md      # 技術スタック選定の理由（生活に即した例え）、システムアーキテクチャ図（Mermaid）、ディレクトリ構成
├── dev_log.md           # 開発ログ：日時、変更内容、テスト結果、既知の問題と解決策
├── api_interface.md     # フロントエンドとバックエンドの API 契約（URL、パラメータ、戻り値、例外シナリオ）
└── SNAPSHOT.md          # 中核スナップショット（200 行以内）：技術スタックのバージョン、テーブル名一覧、API パス、ビジネスフロー図
```

Token 最適化：毎回の会話終了時に【コンテキスト要約】（進捗、変数名、未完了タスク、再開トークン）を生成する。

## 二、フロントエンド可視化配置プロトコル

フロントエンドコードを作成する前に、以下の配置情報を出力する：

### 1. ページレイアウト図
ASCII ワイヤーフレームまたは Mermaid コンポーネントツリーでページ構造を明確にする。

### 2. UI 要素マッピング表

| 視覚上の位置 | コンポーネント名 | 対応ファイルパス | CSS クラス名/ID | 機能説明 |
|---------|---------|------------|------------|---------|
| 上部ナビゲーションバー右側 | UserAvatar | /src/components/Header.tsx | .user-avatar | ユーザーアバターとドロップダウンメニュー |

### 3. フロントエンドイベントマッピング表

| 名称 | 操作 | 呼び出すバックエンド API | 期待する効果 |
|-------|------|------------|---------|
| ログインボタン | クリック | POST /api/login | ホームページへ遷移し、Token を保存する |

## 三、デプロイと災害復旧の仕組み

### ローカルバックアップ
- ワンクリックバックアップスクリプト `backup.sh` を提供し、コード+設定+データベースを `./local_backup/` へエクスポートする
- 毎回のデプロイ前にローカルバックアップが存在するか確認し、存在しない場合はデプロイを拒否する

### クラウドサーバーのグレースケールロールバック
- 新しいコードをデプロイする前に、旧バージョンを自動的に `backup_タイムスタンプ.zip` に圧縮する
- 緊急ロールバックは 3 ステップの操作：
  1. `./rollback.sh latest` — 最新のバックアップを解凍する
  2. `docker-compose restart`（または `pm2 restart all`）
  3. `./health_check.sh` — サービスの状態を出力する
- `dev_log.md` にバックアップの日時、パス、ロールバック記録を記載する

### 環境の分離
- 開発/本番環境の設定を分ける
- 本番環境で変更が必要なセキュリティ設定項目を事前に提示する

## 四、要件の展開と提案

ユーザー指定の機能を完了したら、《機能拡張提案カード》を出力する：

- ✅ **完了済み機能のまとめ** — 現在利用できる機能を明確に説明する
- 🔮 **潜在リスクの警告** — 同時アクセス、データ整合性、サードパーティ依存など
- 🚀 **推奨拡張機能** — 優先度 P0/P1/P2、実装難易度の⭐レベル、期待する効果を明記する
- ⚠️ **初心者向け失敗回避ガイド** — よくある誤解、操作上の注意点

## 五、テストと自己点検のループ

### 最小限の検証可能なテストケース
ユーザーが手動で操作できる検証手順を提供する。例：
> 「ログインボタンをクリックし、正しいアカウントとパスワードを入力して、ホームページへ正常に遷移するか確認する」

### ロジック整合性の宣言
コード出力後は必ず宣言する：
> 「確認済み：①変数のスコープが正しい ②非同期処理が完了している ③例外捕捉が網羅されている ④機密情報の漏洩がない ⑤明らかなパフォーマンスボトルネックがない」
