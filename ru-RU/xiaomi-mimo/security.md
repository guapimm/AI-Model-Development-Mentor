# Подробное руководство по правилам безопасности

## 1. Управление ключами и конфигурацией

- Запрещено хардкодить в коде какие-либо ключи, пароли или API Token
- Единообразно использовать переменные окружения; в коде ссылаться только на имена переменных
- Все элементы конфигурации выносить в файл `.env.example` (без реальных значений — только имена переменных)
- Файл `.env` для production-окружения добавить в `.gitignore`

## 2. Валидация пользовательского ввода

- Весь пользовательский ввод должен проходить проверку типов (например, числовые поля должны отклонять строки)
- Задавать разумные ограничения длины (например, имя пользователя: 2–50 символов)
- Отклонять инъекции спецсимволов (ключевые слова SQL, HTML-теги и т. п.)
- Для загрузки файлов ограничивать тип и размер, проверять MIME-тип

## 3. Безопасность базы данных

- Обязательно использовать параметризованные запросы или предкомпилированные ORM-запросы
- Запрещено собирать SQL конкатенацией строк
- Чувствительные поля (пароли) должны храниться в виде хешей (bcrypt/argon2)
- Пароль в строке подключения к базе данных хранить в переменной окружения

## 4. Защита фронтенда от XSS

- Весь динамически отображаемый контент должен проходить HTML-экранирование
- Использовать встроенные механизмы экранирования фреймворков (например, `{}` в React, `{{}}` во Vue)
- Запрещено выводить пользовательский ввод напрямую через `innerHTML` или `v-html`
- Для Cookie устанавливать флаги `HttpOnly` и `Secure`

## 5. Безопасность файловой системы

- Все операции с путями файлов должны проверяться — защита от Directory Traversal (`../`)
- Ограничивать доступный диапазон каталогов с помощью белого списка
- Переименовывать загруженные файлы в случайный UUID, не сохраняя исходное имя файла

## 6. Безопасность внешних запросов

- Для всех HTTP-запросов задавать таймаут (рекомендуется 5–10 секунд)
- Реализовать стратегию повторных попыток (не более 3 раз, экспоненциальная задержка)
- Проверять SSL-сертификаты; пропуск проверки сертификата запрещён

## 7. Обработка исключений

- Все исключения должны перехватываться через try-catch
- В production-окружении не возвращать клиенту исходный стек вызовов
- Логировать ошибки (время, ID запроса, тип ошибки)
- Для чувствительных операций (неудачный вход, недостаток прав) вести журнал аудита

## 8. Безопасность производительности

- Учитывать узкие места производительности интерфейсов, при необходимости добавлять кэш (Redis)
- Оптимизировать медленные запросы, добавлять индексы базы данных
- Большие файлы загружать фрагментами или потоково
- Предотвращать атаки на исчерпание ресурсов (ограничение частоты запросов)
